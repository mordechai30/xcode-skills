# Privacy & Telemetry

What we collect, why, and how to turn it off.

MobileBuildMCP uses [Sentry](https://sentry.io) for internal error monitoring. This helps track crashes and unexpected faults in the server code itself so the team can fix them. By default, the scope is strictly limited to MobileBuildMCP's own runtime failures.

<a id="whats-sent"></a>

## What's sent[#](#whats-sent)

- **Internal MobileBuildMCP failures only**: for example, daemon or MCP runtime faults, unexpected exceptions in server code.
- **Internal operational logs** only when the server explicitly tags an event for Sentry. Standard console logs are not auto-forwarded.
- **Redacted event payloads**: user home paths become `/Users/<redacted>/...`, request/user context is scrubbed before send.

<a id="whats-never-sent"></a>

## What's never sent[#](#whats-never-sent)

- **User-domain errors**: project build/test failures, invalid user config, missing scheme/destination, simulator/app-state errors are not sent.
- **Tool inputs and outputs**: tool arguments and return values are not captured by MCP wrapper telemetry (`recordInputs: false`, `recordOutputs: false`).
- **Environment variables and system state**: not attached as telemetry tags.
- **Source code, build artifacts, binary content, certificates, provisioning profiles**: none of these leave your machine.

<a id="opting-out"></a>

## Opting out[#](#opting-out)

Set the env var in your MCP client config:

json

```
{
  "env": {
    "MOBILEBUILDMCP_SENTRY_DISABLED": "true"
  }
}
```

Or in your project config:

yaml

```
sentryDisabled: true
```

Or at the shell:

shell

```
export MOBILEBUILDMCP_SENTRY_DISABLED=true
```

Any of the three paths fully disables the SDK.

<a id="why-telemetry-at-all"></a>

## Why telemetry at all[#](#why-telemetry-at-all)

MobileBuildMCP sits between your agent and Xcode's build system. A lot of edge cases (weird simulator states, odd Xcode versions, rare xcodebuild output shapes) only surface when something breaks in the wild. Narrow, opt-outable error telemetry is how the team catches and fixes those without asking every user to file a bug.

The telemetry scope was tightened in [v2.1.0](https://github.com/getsentry/MobileBuildMCP/blob/main/CHANGELOG.md) to capture only internal runtime failures after [#204](https://github.com/getsentry/MobileBuildMCP/issues/204).
